## 一、這份教材是什麼形狀

理解這一點，後面所有維運動作都會變得很簡單：

- **單一自包含 HTML 檔**（`index.html`，約 460 KB）。所有 CSS、JavaScript、SVG 圖都在裡面。
- **零建置流程**：沒有 npm、沒有打包、沒有框架。你改完存檔就是成品。
- **零後端**：純靜態網站，所有互動都在瀏覽器裡跑。
- **唯一的外部連線**是 Google Fonts（三套字型）。斷網時字型會退回系統字型，內容完全不受影響。
- **狀態存在讀者自己的瀏覽器**：驗收清單的勾選狀態存在 `localStorage`，不會回傳任何伺服器。

> **這代表**：部署＝把一個檔案放上靜態主機。改版＝改那個檔案再放一次。沒有其他步驟。

### 倉庫結構

```
vocabuddy/
├── index.html            # 教材本體，唯一的成品（約 460 KB）
├── glossary.md           # 詞彙表獨立檔（內容與教材附錄 C 一致，112 條）
├── README.md             # 倉庫門面
├── LICENSE               # CC BY-NC-SA 4.0（內容）＋ MIT（程式碼片段）
├── CHANGELOG.md          # 版本沿革
├── .gitignore
├── docs/
│   └── MAINTENANCE.md    # 本文件：部署、維運與改版
└── tools/
    └── check.py          # 改版後的結構自動檢查（§4.5）
```

## 二、首次部署（已完成，記錄備查）

1. **建立倉庫**：`tw-ytp/vocabuddy`，**public**
   （GitHub Pages 免費方案要求 public；轉公開前務必確認歷史裡沒有金鑰或個資——這正是教材 4.1／4.4 教學生做的那件事，而 Lab 1 步驟 4 就已經向學生預告了這一步）
2. **推送內容**到 `main` 分支
3. **開啟 Pages**：Settings → Pages → Build and deployment → Source 選 **Deploy from a branch**，分支 `main`、資料夾 `/(root)`，存檔
4. 等約一分鐘，網址生效：**<https://tw-ytp.github.io/vocabuddy/>**
5. **驗證**：桌機開一次、手機開一次、無痕視窗開一次（確認不是快取）

### 為什麼用 GitHub Pages 而不是別的

因為**教材第四篇 4.1 正在教 GitHub Pages**。主辦單位用同一套方法發布這份教材，本身就是最好的示範。若日後需要自訂網域或更好的節點速度，Cloudflare Pages 可以直接連同一個 GitHub 倉庫自動部署，兩者並存不衝突——需要時再加，現在不需要。

## 三、改版流程

### 3.1 正規流程（建議所有改動都走這條）

沿用教材第一篇教的 GitHub Flow：

```bash
git switch -c fix/appendix-b-2026-10       # 1. 開分支
# ...改 index.html...
git add index.html
git commit -m "docs: 更新附錄 B 工具區（2026-10 重查）"
git push -u origin fix/appendix-b-2026-10  # 2. 推上遠端
# 3. 開 PR，請另一位維護者 review
# 4. merge 後約一分鐘，正式站自動更新
```

**merge 進 `main` 就等於上線**——這是教材 4.1 講的「main＝正式版」，在維運端一樣成立。所以：**不要直接 push 到 `main`**。

### 3.2 大改版：先在 Artifact 試閱，再同步進倉庫

教材在 Claude 的 Artifact 上有一份「試閱版」，用於改版期間的快速迭代與內部試閱。兩者的分工：

| | Artifact | GitHub Pages |
|---|---|---|
| 定位 | **Pilot／預覽**：改版期間快速迭代 | **正式版**：對外公告的網址 |
| 更新 | 隨時 | 走 PR，merge 即上線 |
| 版本 | 平台自動保存每次發佈 | Git 歷史＋tag |

> ⚠️ **Artifact 的分享 pin**：Artifact 的分享連結會被「釘」在某一個版本上。發佈新版之後，**必須在 Artifact 介面把分享版本更新到最新版**，拿到連結的人才看得到新內容。改完務必用**無痕視窗**開一次分享連結確認。
>
> 這個坑踩過一次就不會忘：發佈了，但所有人看到的還是舊版。

**同步到倉庫時的一個技術差異**：Artifact 發佈時平台會自動補上 `<!doctype html><html><head>…</head><body>` 外殼，所以交給 Artifact 的檔案不含這層外殼；倉庫裡的 `index.html` **必須是完整 HTML 文件**（含 doctype、`<head>`、`<title>`、favicon 等）。同步時記得補上，或直接沿用倉庫既有的 head 區塊、只換 `<body>` 內容。

### 3.3 版本號與 tag 慣例

| 情況 | 版本 | 動作 |
|---|---|---|
| 新增一整篇、動到導讀或全站結構 | 大版（v2.0 → v3.0） | 打 tag，寫 CHANGELOG |
| 新增／改寫章節或 Lab | 次版（v2.0 → v2.1） | 打 tag，寫 CHANGELOG |
| 附錄 B 重查、錯字、連結修正 | 修訂（v2.0 → v2.0.1） | 不必打 tag，CHANGELOG 記一行 |

改版本號時**三處要一起改**（漏改任一處就會前後不一致）：

1. 側欄的 `線上自學教材・v2.2`
2. 附錄 B 頁尾的 `教材版本 v2.2（…）`
3. `CHANGELOG.md`

```bash
git tag v2.1 && git push --tags
```

## 四、內容維護：改什麼、改哪裡

### 4.1 最重要的一條規則

**會過期的東西不進正文。**

教材正文只寫**長期不變的原理與流程**；所有會隨時間改變的數字、名稱、網址、方案、版本，全部集中在**附錄 B 時效資訊表**，每一欄都標了查證日期與重查方式。

> 這是這份教材能長期維護的關鍵。改版時你多半只需要動附錄 B 那一頁，正文一個字都不用改。

### 4.2 附錄 B 的重查節奏

| 區塊 | 建議重查頻率 | 為什麼 |
|---|---|---|
| **第五篇・AI-Native 開發區** | **每次開課前，至少每季** | 變動最快。工具每個月都在改：方案、路徑、支援與否 |
| 第二篇（模型名稱、API、SDK） | 每次開課前 | 模型名稱與免費額度變動頻繁 |
| 第一、四篇（Git、GitHub、Pages、Actions） | 每半年 | 相對穩定 |
| 本地模型（附錄 E） | 每半年 | 型號會換代 |

重查時**只改「撰寫時的狀態」與「查證日期」兩欄**，不要改「項目」與「重查方式」——那兩欄是給下一個人用的。

### 4.3 查不到就留白

附錄 B 有一列叫「**刻意留白：查不到的項目**」。這不是偷懶，是教材的紀律：

> **寧可留白，也不要猜。** 一格錯誤的資訊，會讓學生照著做然後卡住，比沒有資訊更糟。

維護時若查證不到，把它移進那一列並寫明你試過什麼，不要憑印象填。

### 4.4 幾個容易漏掉的連動點

改動內容時，這些地方會一起受影響：

| 你改了 | 記得一起改 |
|---|---|
| 新增或刪除章節 | 側欄導航、`PAGES` 路由陣列、前後頁的 `pgnav`、所在篇的「章節地圖」卡片 |
| 新增 Lab | 導讀的 Lab 總數、附錄 D 的檢查點 tag 對照表 |
| 新增動圖 | `FIGS` 物件裡的說明文字陣列（**步數必須與 SVG 的 `data-s` 最大值相同**） |
| 新增術語 | 附錄 C **與** `glossary.md`（兩份要一致） |
| 改版本號 | §3.3 的三處 |
| 新增驗收清單項目 | `data-ck` 的 id 不可重複（重複會導致勾選狀態互相干擾） |

### 4.5 改完之後的自動檢查

檢查腳本已收錄在 [`tools/check.py`](../tools/check.py)，每次改版後跑一次，可以抓出上表大部分的漏改：

```bash
python3 tools/check.py
```

它檢查七件事：

1. 側欄／路由（`PAGES`）／頁面三者一致
2. 站內連結沒有指向不存在的頁面
3. 每幅動圖的 HTML 與 JS 說明對得上，且**步數相同**
4. HTML 標籤平衡
5. 驗收清單 `data-ck` id 不重複
6. 測驗題號不重複、正解在選項內、選項順序正常、`name` 一致
7. 版本號在側欄與附錄 B 頁尾一致

通過會印出頁面數、動圖數、題數與版本號；有問題則逐條列出並以非零狀態碼結束（可接進 CI）。

**自動檢查抓不到的**，仍需人工看：內容正確性、前後文一致、附錄 B 是否過期、新章節的語調是否一致。

### 4.6 人工複查清單（每次改版）

- [ ] 亮／暗兩種主題都看過（瀏覽器開發者工具可切換 `prefers-color-scheme`）
- [ ] 手機寬度看過（側欄抽屜、表格橫向捲動、動圖縮放）
- [ ] 新增的動圖逐步點過一遍，每一步的圖與說明對得上
- [ ] 新增的術語在正文第一次出現時寫了全名（中文＋英文）
- [ ] 沒有把會過期的資訊寫進正文（§4.1）
- [ ] 版本號三處一致（§3.3）

## 五、開課前檢查清單

開課**前一週**做，不要當天做：

- [ ] 附錄 B **全表**重新查證一次（尤其第五篇區，見 §4.2）
- [ ] 各工具的官方安裝頁網址還通嗎？（Lab 11 步驟 1 的表格）
- [ ] 帳號與費用那一列還正確嗎？各家方案變動頻繁
- [ ] 教材網址在**未登入**的裝置上打得開
- [ ] 手機開一次，走完一個 Lab 的驗收清單（確認勾選狀態會保存）
- [ ] 若有配套的範例 repo：檢查點 tag 是否齊全（附錄 D 的對照表）
- [ ] 若同時維護 Artifact 試閱版：**分享 pin 是否指向最新版**（§3.2）

## 六、疑難排解

| 症狀 | 原因與解法 |
|---|---|
| **改了但網站沒變** | ① Pages 部署要一兩分鐘；② 瀏覽器快取——用無痕視窗或強制重新整理確認；③ 確認 merge 進的是 `main`；④ 看 repo 的 Actions 分頁，Pages 部署有沒有跑成功 |
| **網址 404** | 確認 repo 是 **public**、Pages 來源選 `main` / `(root)`、根目錄檔名是 `index.html`（小寫） |
| **字型變成系統預設** | Google Fonts 沒載入。可能是網路環境擋了 `fonts.googleapis.com`——**內容不受影響**，可接受。若場地網路常擋，可考慮把字型改為系統字型堆疊 |
| **動圖點下一步沒反應** | 該圖的 `data-fig` 名稱與 `FIGS` 裡的鍵不一致，或說明陣列步數不符。跑 §4.5 的檢查腳本 |
| **側欄某一項點了跳回導讀** | 該頁面 id 不在 `PAGES` 路由陣列裡。跑檢查腳本 |
| **驗收清單勾了又跑掉** | `data-ck` 的 id 重複。跑檢查腳本 |
| **Artifact 分享連結看到舊版** | 分享 pin 沒移動（§3.2） |
| **檔案越來越大、載入變慢** | 目前約 460 KB，仍在單檔可接受範圍。若超過 1 MB，考慮拆頁——教材本來就按「篇」模組化，拆頁成本很低 |

## 七、回報與貢獻

教材附錄 B 頁尾對學生寫著：「發現錯誤或有改善建議？歡迎直接開一個 issue」，並連到本倉庫的 issue 頁。**請確保 issue 是開著的**，並指派一位維護者定期處理。

建議的 issue 標籤：

| 標籤 | 用途 |
|---|---|
| `過期資訊` | 附錄 B 的內容需要更新 |
| `錯字` | 錯字、標點、格式 |
| `內容錯誤` | 技術內容有誤 |
| `教學建議` | 講不清楚、建議補充 |
| `Lab 卡關` | 學生實作時遇到教材沒寫到的狀況——**這類最有價值**，請補進該 Lab 的「卡住了？」區塊 |

> 助教課後彙整的卡關清單，就是「卡住了？」區塊的補充來源。每一屆跑完，教材就更耐用一點。
